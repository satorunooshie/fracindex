# Specification

This document defines the behavior of `github.com/satorunooshie/fracindex`.

## Key Space

An `Indexer` represents one fractional-index key space. Keys generated by one
`Indexer` must only be compared with keys from another `Indexer` when both were
created with the same options.

`New()` without options creates the default key space:

```text
digit alphabet: 0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz
head alphabet:  ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz
```

The default key space is intended to be byte-compatible with Rocicorp-style
base62 fractional-indexing keys.

## Ordering

Keys are ordinary strings. The ordering contract is bytewise lexicographic
ordering:

```go
slices.Sort(keys)
```

Any system that stores or compares keys must preserve that same byte order.

## Bounds

`KeyBetween(prev, next)` returns one key `k` such that:

```text
prev == "" || prev < k
next == "" || k < next
```

`NKeysBetween(prev, next, n)` returns `n` keys in ascending order. For every
returned key `k`:

```text
prev == "" || prev < k
next == "" || k < next
```

An empty `prev` means the beginning of the key space. An empty `next` means the
end of the key space. When both bounds are non-empty, `prev` must sort before
`next`.

## Key Format

Each key has an integer part followed by an optional fractional part.

```text
a0V
|`- fractional part
`-- integer part
```

The first byte is a head byte. It determines the integer-part length and whether
the integer is in the negative or positive side of the key space. Remaining
integer bytes and all fractional bytes come from the digit alphabet.

The fractional part must not end with the zero digit. This keeps generated keys
canonical.

## Alphabets

Built-in alphabet sets:

Set | Alphabet
--- | ---
`Base16` | `0123456789ABCDEF`
`Base32` | `0123456789ABCDEFGHJKMNPQRSTVWXYZ`
`Base36` | `0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ`
`Base62` | `0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz`
`Base94` | Printable ASCII bytes from `!` (`0x21`) to `~` (`0x7e`)
`Base95` | Printable ASCII bytes from space (`0x20`) to `~` (`0x7e`)

`WithAlphabetSet(set)` sets the same built-in alphabet for digit and head
positions. The selected alphabet is rejected unless it satisfies both digit and
head constraints.

`WithDigitAlphabetSet(set)` sets the built-in alphabet used for integer and
fractional digits.

`WithHeadAlphabetSet(set)` sets the built-in alphabet used for integer-part
heads.

`WithAlphabet(chars)` sets the same byte alphabet for digit and head positions.
It is rejected unless the alphabet satisfies both digit and head constraints.

`WithDigitAlphabet(chars)` sets the byte alphabet used for integer and
fractional digits.

`WithHeadAlphabet(chars)` sets the byte alphabet used for integer-part heads.
The head alphabet is split into two equal halves:

```text
first half:  negative integer lengths
second half: positive integer lengths
```

Alphabet constraints:

- At least two bytes
- Strictly sorted by byte value
- No duplicate bytes
- No NUL bytes
- Head alphabet length must be even

Alphabets are byte alphabets, not Unicode character alphabets. The
`Base*DigitAlphabet` constants expose the raw byte strings behind the built-in
sets for callers that need to compose custom options.

## Max Length

`WithMaxLength(n)` sets a maximum key length in bytes.

If a generated or validated key exceeds that length, the operation returns
`ErrKeyspaceExhausted`.

This does not mean the mathematical interval is empty. It means the interval is
exhausted under the configured key-space constraints.

## Errors

Errors are wrapped with sentinel values so callers can use `errors.Is`.

```go
errors.Is(err, fracindex.ErrInvalidRange)
errors.Is(err, fracindex.ErrKeyspaceExhausted)
```

Sentinels:

- `ErrInvalidOption`
- `ErrInvalidAlphabet`
- `ErrInvalidKey`
- `ErrInvalidRange`
- `ErrInvalidCount`
- `ErrRangeUnderflow`
- `ErrRangeOverflow`
- `ErrKeyspaceExhausted`

## Non-goals

- No package-level default generator
- No float conversion
- No database integration
- No automatic rebalance
- No CRDT conflict-resolution policy
